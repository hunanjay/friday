## 2. 背景与痛点分析

### 2.1 现状与痛点
1. **静态通讯录的局限**：Outlook / 手机通讯录只存储姓名、电话、邮箱等静态元数据，无法保存动态上下文（如："喜好喝普洱茶"、"下个月要发布新 SDK"、"小孩考研"）。
2. **记忆衰减与关系流失**：商务/职场交流频繁，细微的人际记忆极其容易遗忘。
3. **传统 CRM 录入门槛高**：传统销售/个人 CRM 工具要求用户像做 Excel 填表一样手动打字录入，违反人性，导致弃用率极高。

### 2.2 解法与产品价值
* **AI 无感化沉淀**：用户正常在 Chat 里聊天或记录 Memo 笔记，后台 AI 自动完成**人名识别 -> 事实提取 -> 联系人匹配 -> 结构化沉淀**。
* **双向增强 (Agent RAG)**：在后续对话中，Agent 自动调取联系人记忆进行精准问答与沟通策略准备。

## 3. 产品核心逻辑与流程

```
┌─────────────────┐       ┌────────────────────────┐       ┌────────────────────────┐
│  User Input     │  ───► │  AI Backstage Worker   │  ───► │  Storage & Retrieval   │
│ (Chat / Memos)  │       │ (NER + Fact Extract)   │       │ (Postgres + Agent Tools│
└─────────────────┘       └────────────────────────┘       └────────────────────────┘
```

1. **输入触发**：用户在 Chat 发送消息或在 Memo 保存笔记。
2. **异步提取**：后台模型（`DRAFT_MODEL` / `glm-4-flash`）提取实体（人名）与分类事实片段（职业、喜好、家庭、商务、事件、其他）。
3. **联系人归档**：匹配 Outlook 联系人列表，匹配成功归档到对应联系人名下，未匹配归档到名字下。
4. **展示与问答**：Contacts 详情页提供独立的 **AI 记忆面板**；Agent Tool 提供全局人脉搜索与记忆检索。

## 5. 非功能需求 (Non-Functional Requirements)

1. **性能与体验**：记忆提取必须在后台异步执行（Fire-and-forget），不得阻塞 Chat 消息的实时 SSE 流响应或 Memo 保存响应。
2. **成本控制**：提取服务采用轻量高效模型（如 `glm-4-flash` / `DRAFT_MODEL`），单次输入控制在 2000 字符内，限制单次最多提取 5 个人名。
3. **数据隐私与隔离**：所有记忆数据严格绑定 `user_id`，利用 Postgres RLS（Row Level Security）隔离，数据保存在应用私有库中，不会暴露给第三方。
